| 启动单个 Battle.net | 成功启动并加载对应 Windows 用户数据 |
| 启动多个 Battle.net | ≥5 个实例同时运行 |
| 登录状态隔离 | 不同实例保持不同 Battle.net 登录状态 |
| 游戏目录共享 | 所有实例识别同一 WoW 安装目录 |
| 错误凭据 | 提示“用户名或密码错误”并记录日志 |
| 缺失 Battle.net 路径 | 提示重新配置路径 |

| 快捷方式 | 双击 `.lnk` 直接启动对应实例,无主界面 |
| 重启 Windows 后首次启动 | 目标用户未登录桌面、无残留战网实例时,读取原有登录状态与游戏安装位置,能够进入游戏;首次 / 第二次启动行为一致(战网自身要求重新认证的情况需单独判断) |
| 管理员 / 普通权限启动 BPM | 两种方式都使用配置绑定的目标用户数据;不读取 BPM 所属用户的战网配置 |

| 同名系统用户 | 拒绝自动创建,原用户密码和数据保持有效 |
| 普通权限创建 | 清晰提示以管理员身份运行,不创建系统用户 |
| 创建中途失败重试 | 保留编辑窗口,重试不重复创建或覆盖已保存凭据,最终可保存 BPM 配置 |
| 用户配置路径缓冲区 | 原生调用使用不超过 260 字符的缓冲区,不再产生由 1024 字符参数引起的 `0x800706F7` |
| 重启后恢复未完成账号 | 添加账户时选择“仅初始化已有本地用户”,使用原 Windows 密码完成设置;不重新创建用户、不重置系统密码 |
| 无默认浏览器的新用户 | 不提前登录目标桌面或写关联，管理员 BPM 启动前辅助就绪；真实认证网页以目标用户打开，完成认证后可进入游戏，操作者默认浏览器不变 |
| 登录辅助重试 | 战网取消旧请求后重试，新请求自动交接，重复事件不开重复网页；战网进程交接/重启后本轮仍有效 |
| 权限/浏览器/入口不兼容 | 战网照常启动，显示具体辅助状态；可打开绑定用户的手动桌面登录指引，不能宣称已认证 |
| 辅助开关与旧配置 | 旧 JSON 缺少字段时默认启用，明确关闭可保存并复载，编辑/导入不遗留旧身份监听 |
| 快捷方式辅助 | 新快捷方式不强制 Windows 提前提升；首次由 BPM 请求管理员权限，已有实例直接转交；后台保持 15 分钟辅助窗口，辅助失败时显示主界面，再次启动不产生相同用户的重复辅助 |
| 长链接与隔离 | 超过 1024 字符的完整地址原样经内存管道传递；拒绝错误 PID、属主、路径、站点、重复字段和过期事件；配置/日志/文件无完整地址 |
| 私人程序目录 | 目标用户无法读取原 Debug 目录时，受限缓存的助手仍可连接并以正确 SID 应答；原目录 ACL 不变，缓存只含程序文件，目标不能修改缓存文件 |
| 结束与异常 | 到期/关闭 BPM 后无所属实时会话，异常终止后下次清理已退出进程的遗留会话；其他用户/其他实例会话不被停止 |
| 小屏幕与缩放 | 主窗口最小尺寸可滚动查看列表；账号编辑小屏幕可滚动到保存按钮；键盘可聚焦重试和手动指引 |
| 单实例 | 连续打开只保留一个主进程，最小化后再次打开恢复原窗口；已有实例时普通启动无需重复 UAC；主进程关闭后可重新打开 |
| 单实例快捷方式 | 不同配置 GUID 均转交现有进程，同配置并发启动有忙碌保护；后台模式可转为主界面，旧辅助不因后续快捷方式退出 |
| 单实例隔离及退出 | 助手不占主实例；不同 Windows 用户/SessionId 独立；拒绝其他用户、未提升服务端及错误数据；初始化排队、拒绝接收及连接断开不误报已执行 |

### 开机首次启动回归步骤

1. 先在配置绑定的 Windows 用户下完成一次战网登录和游戏目录定位,确认游戏可以正常进入,记录游戏错误码(若有)。
2. 重启 Windows,只登录运行 BPM 的用户,不登录目标用户桌面、不手动启动战网。
3. 运行新构建的 BPM,点击配置的启动按钮,检查是否读取原有登录状态、是否仍需定位游戏目录、是否能够进入游戏。
4. 手动完全退出该用户的战网后再次启动,对比前后行为;另一次重启后用 `--launch` 快捷方式检查同样场景。
5. 如仍失败,保留游戏完整错误码、BPM 日志和目标用户下的战网日志,继续检查目录权限及战网自身认证状态。单元测试通过不能替代此项真实多用户验收。
